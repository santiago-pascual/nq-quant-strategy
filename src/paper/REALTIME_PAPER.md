# Realtime Paper (PAPER only)

The realtime service routes completed MNQ bars through the existing causal
market context, forward-filter HMM, four strategies, risk engine, conflict
control, and in-memory simulated broker. The runner rejects any mode other than
`PAPER`; it does not submit broker orders.

## Deterministic replay commands

Run a replay through the realtime market-data interface:

```powershell
python -m src.paper.run_realtime_paper --command run --mode PAPER `
  --replay-start 2024-08-27T00:00:00Z --replay-end 2024-08-28T23:59:00Z `
  --output-dir results/paper/realtime-smoke
```

A new run requires an unused output directory. Resume uses the last valid
checkpoint and replays only bars strictly after its last committed timestamp:

```powershell
python -m src.paper.run_realtime_paper --command run --mode PAPER `
  --replay-start 2024-08-27T00:00:00Z --replay-end 2024-08-28T23:59:00Z `
  --output-dir results/paper/realtime-smoke --resume
```

Operational commands:

```powershell
python -m src.paper.run_realtime_paper --command stop --output-dir results/paper/realtime-smoke
python -m src.paper.run_realtime_paper --command status --output-dir results/paper/realtime-smoke
python -m src.paper.run_realtime_paper --command events --output-dir results/paper/realtime-smoke --count 50
python -m src.paper.run_realtime_paper --command verify-checkpoint --output-dir results/paper/realtime-smoke
python -m src.paper.run_realtime_paper --command shadow-report --output-dir results/paper/realtime-smoke
```

The stop command writes `stop.request`. The running service observes it, asks
the source to stop, finishes already-buffered completed bars, checkpoints, and
shuts down. An adapter's `stop()` must unblock its `bars()` iterator.
Ctrl+C, SIGTERM, and the Windows console break signal request the same graceful
shutdown. The service checkpoints the last fully processed bar before exit.

## Output files

- `events.jsonl`: append-only structured events, with a monotonically increasing
  sequence, UTC timestamp, run ID, severity, and symbol.
- `bootstrap_checkpoint.json`: causal history seed captured before the first
  replay bar; used by deterministic shadow replay.
- `paper_checkpoint.json`: atomic, checksummed runtime state. A valid backup is
  retained as `paper_checkpoint.json.bak`.
- `hmm_refits.jsonl`: model version, training interval/identity, scaler/HMM
  identities, raw state profiles, and fit duration for each scheduled refit.
- `status.json`: atomically replaced machine-readable monitoring snapshot.
- `daily_shadow_parity.json`: deterministic event parity report from
  `shadow-report`; detailed rerun events live under `shadow_replay/`.
- `paper_analytics.sqlite3` plus SQLite WAL files: versioned persistent facts
  and recalculable trade/report data. The database uses WAL, foreign keys,
  full synchronous commits, a 30-second busy timeout, and event-ID
  idempotency. Schema migrations are controlled by SQLite `user_version`.
- `daily_reports/YYYY-MM-DD.json` and `.md`: machine-readable and readable
  summaries generated for every session date in the stored market-bar history
  on shutdown.
- `cost_profile.json`: immutable copy of the explicit fee profile used by the
  run.

## Realtime Paper costs

Realtime runs require an explicit `--cost-config` JSON profile. The checked-in
TopstepX MNQ profile sets zero artificial slippage and charges per contract on
each simulated fill: $0.25 commission, $0.35 exchange fees, and $0.01
regulatory fee per side ($1.22 round turn). Gross P&L is the signed fill-price
difference multiplied by MNQ's $2 point value and quantity. Net P&L subtracts
the separately stored commission, exchange, and regulatory costs. Realized R
uses the net result divided by initial dollar risk. Fill prices remain those
generated by the existing Paper execution rules; no synthetic slippage is
added. A new run must use zero `--price-offset`.

The profile is for TopstepX and should be rechecked before use because fees can
change. See Topstep's [TopstepX commissions and fees](https://help.topstep.com/en/articles/8284213-topstepx-commissions-and-fees)
and [Live Funded Account costs](https://help.topstep.com/en/articles/8284229-what-are-the-costs-in-the-live-funded-account).
IBKR is not used as the execution-cost source.

Example:

```powershell
python -m src.paper.run_realtime_paper --command run --mode PAPER `
  --replay-start 2024-08-27T00:00:00Z --output-dir results/paper/realtime-smoke `
  --cost-config src/paper/config/topstepx_mnq_fees_2026-07.json
```

## Analytics and read-only access

The normalized database retains canonical bars and source/contract/timestamps,
feature snapshots, candidates and rejection reasons, risk decisions, orders,
fills, position lifecycle, HMM observations/refits, session/calendar identity,
account snapshots, configuration identities, checkpoints, shadow comparisons,
and generated reports. Trade economics include costs, net P&L, initial-risk R,
duration, and bar-derived MAE/MFE where market observations are available;
unrecoverable reference prices or fields stay null.

The stable `PaperAnalyticsReader` is read-only and exposes status, open
positions, per-strategy statistics, recent trades/trade details, latest HMM
state, risk, event timeline, daily reports, and shadow parity. The CLI
`--command analytics` uses this reader. It does not control or gate the trading
engine. Daily reports include gross/net P&L, costs, trade/R statistics,
drawdown, candidate and risk accounting, HMM occupancy/transitions/refits,
system-event counts, and technical/operational/statistical statuses. Sharpe
and Sortino are per-trade, unannualized closed-net-R ratios with downside
target R=0. Fewer than 25 closed trades is YELLOW; profitability alone never
sets RED. A shadow parity discrepancy is RED. Historical baseline comparison
is explicitly UNAVAILABLE until a compatible baseline mapping is configured.

Rolling 25-, 50-, and 100-trade summaries are included when enough stored
closed trades exist. The current schema does not fabricate confidence
intervals when there is no compatible empirical baseline.

## Backup and restore

Create a consistent SQLite snapshot while Paper is running or stopped; this
uses SQLite's online backup API, so do not copy only the main database file
while WAL is active:

```powershell
python -m src.paper.run_realtime_paper --command backup-database `
  --output-dir results/paper/realtime-smoke `
  --backup-path D:/paper-backups/realtime-smoke-2026-10-07.sqlite3
```

The command checks the backup's SQLite integrity before atomically publishing
the destination. Back up `events.jsonl`, `paper_checkpoint.json`, its `.bak`,
`bootstrap_checkpoint.json`, `hmm_refits.jsonl`, cost/calendar profiles, and
daily reports alongside the database. Restore only while the Paper process is
stopped: preserve the current directory, copy the verified backup to
`paper_analytics.sqlite3`, remove stale `paper_analytics.sqlite3-wal` and
`paper_analytics.sqlite3-shm` files, then run `--command analytics` and
`--command verify-checkpoint` before resuming. A database backup alone does
not restore account/strategy state; restore the matching verified checkpoint
and the matching code, model, calendar, and cost identities too.

## Deployment preparation and limits

Use a dedicated non-root Linux account, an encrypted persistent volume, a
private output directory with restrictive permissions, and an external
secret store/environment for future provider credentials. Keep the SQLite DB,
JSONL trail, checkpoint and backups on durable local storage; WAL should not
be placed on a network filesystem. Monitor free disk, process memory, feed
staleness, checkpoint age, event backlog, and DB/write errors. Run one process
per output directory. A supervisor should send SIGTERM and allow the process
to exit after its checkpoint/report flush; do not use a hard kill for routine
shutdown.

`requirements-realtime-paper-py313.lock` pins the runtime versions
observed on Windows 11 x86_64 / CPython 3.13.15. Install in an isolated
environment with `python -m pip install -r
requirements-realtime-paper-py313.lock`; run `python -m pip check`.
Linux x86_64 and aarch64 are not installed or tested in this checkout. PyPI
currently publishes CPython 3.13 Linux ARM64/x86_64 wheels for the core
numerical packages and xgboost, but wheel availability is not an
integration/runtime pass. The lock is not a platform-separated hash lock.
Windows ARM64 wheel compatibility for every required package was not
confirmed; the referenced MSYS2 ARM64 installer was not run.

The scheduled MR refit is known to take about 590 seconds near the end of
available history; this is an observed offline characteristic, not a
validated live-latency SLA. A previous bounded realtime smoke processed 2,714
bars in 304.6 seconds, with a 10,735,761-byte JSONL event file and a
3,567,256-byte current checkpoint (plus a 3,518,250-byte backup). A separate
12-bar fixture run measured 178.5 MB process working set after imports,
183.1 MB peak while running, 3.9 ms mean/15.6 ms max CPU per bar, 92 ms
mean/153 ms max wall time per bar, 307,200-byte SQLite DB, 39,576-byte event
log and 21,413-byte current and backup checkpoints. That fixture had no
historical feature bootstrap, scheduled refit, or closed trade. Its SQLite
file size is dominated by schema/page allocation and cannot be scaled linearly.
The larger smoke's approximately 3.96 KB/bar event-log rate implies about
5.5 MB/day or 2.0 GB/year at 1,400
bars/day, before database, checkpoints, reports, and backups. Treat that as a
rough extrapolation and keep disk headroom. No completed historical bootstrap
timing or S2R refit duration is available; free-host suitability is not
established. Prior observations include an MR expanding refit of about 590
seconds and a warmup attempt exceeding 40 CPU minutes before interruption. A
refit of that length requires measured buffering/backfill capacity before
live use.

A checkpoint binds to the current engine configuration, context config, source
hashes for strategy/risk/HMM/runtime code, and Python/numerical-library
versions. Restore fails closed if those identities differ. At bar scope, event
keys are deterministic so a completed bar replayed after a crash cannot append
its order/fill/position events twice. A torn final JSONL record is repaired only
by the realtime runner before resume; the general Research/Paper logger keeps
its strict validation behavior.

## Future provider contract

No production market-data provider is configured. A future adapter must
implement `MarketDataSource` in `src/paper/realtime_market_data.py`:

- `start()` and `stop()`; `stop()` must unblock iteration.
- `subscribe(symbols, after_timestamp=...)`; on resume, emit every completed
  bar strictly after the supplied UTC timestamp before switching to the live
  stream, without gaps or duplicates.
- `bars()` yields `CanonicalBar` values in strictly increasing timestamp order.
- `health()` reports at least connection and staleness state.

Each `CanonicalBar` must identify MNQ, use a timezone-aware timestamp
normalized to UTC, and contain finite positive OHLC prices, finite nonnegative
volume, and `completed=True`. The provider must preserve the timestamp meaning
and one-minute bar construction used by the validated raw dataset. It should
provide `is_session_final=True` on shortened-session final RTH bars; the service
recognizes the established 15:59 ET close when no explicit marker is supplied.
Provider credentials, reconnect policy, and historical catch-up implementation
remain provider-specific work and are not present in this repository.

The current deterministic replay runner reads only the available internal data
through 2026-08-26 23:59 UTC. It is a development/test source, not a live feed.

## Read-only monitoring HTTP API

Set the token in a protected Windows user environment or secret manager, then
start on loopback in a separate process (this reads the token from that user
environment without putting it in command history):

```powershell
$env:PAPER_MONITORING_TOKEN = [Environment]::GetEnvironmentVariable("PAPER_MONITORING_TOKEN", "User")
if (-not $env:PAPER_MONITORING_TOKEN) { throw "Set PAPER_MONITORING_TOKEN in a protected environment first" }
python -m src.paper.run_realtime_paper --command api `
  --output-dir results/paper/realtime-smoke --api-host 127.0.0.1 --api-port 8765
```

All routes require `Authorization: Bearer <token>`; missing or incorrect
tokens receive 401. Each JSON response has
`{"schema_version":"1.0","data":...}`. GET routes are `/v1/health`,
`/v1/account`, `/v1/strategies`, `/v1/positions`, `/v1/trades`,
`/v1/trades/{trade_id}`, `/v1/hmm`, `/v1/refits`, `/v1/feed`,
`/v1/checkpoint`, `/v1/parity`, `/v1/events`, `/v1/candidates`,
`/v1/daily-reports`, and `/v1/risk`. There are no order-entry routes; POST,
PUT and DELETE return 405. `/v1/health` combines the latest read-only status
snapshot with feed and checkpoint state; `/v1/account` returns the latest
persisted account snapshot and portfolio trade metrics; strategy, trade, HMM,
refit, feed, checkpoint, parity, event and candidate routes expose the
corresponding existing analytics facts. Missing facts remain null, empty, or
`UNAVAILABLE`.

The API does not provide TLS. Keep it bound to loopback; access remotely only
through SSH/VPN or an authenticated TLS-terminating private proxy. Never bind
it directly to a public interface. Environment variables are not checked into
source control.

## Startup and process ownership

Windows bounded replay:

```powershell
.\scripts\start_paper_replay.ps1 -Start 2026-08-25T00:00:00Z `
  -End 2026-08-26T23:59:00Z -OutputDir results/paper/replay-smoke
```

After interruption, inspect `status.json`, verify the matching checkpoint and
resume with the same date range and `-Resume`. Request graceful stop using
`python -m src.paper.run_realtime_paper --command stop --output-dir <dir>` or
Ctrl+C. The Linux replay-only systemd scaffold is
`deploy/systemd/mnq-paper-replay.service.example`; copy
`deploy/systemd/paper.env.example` to `/etc/mnq-paper/paper.env` and change its
replay dates and paths. It contains no secrets. The wrapper resumes only when a
checkpoint exists and refuses existing state without one. It is not a live
service and cannot be enabled for live trading because no provider exists.
The service sends systemd READY, WATCHDOG and STOPPING notifications; the
template restarts failures and rate-limits crash loops. Configure
systemd-journald retention on the host for stdout/stderr. The append-only
event JSONL is not rotated while active; archive it only after a clean stop.
Do not truncate or copytruncate this audit stream.

`RealtimePaperService.run()` holds an advisory OS lock at
`paper_writer.lock` for its configured output directory. Another service using
that directory fails before processing bars, and the OS releases ownership
after process termination. This protects one local output directory only;
it is not distributed fencing for two hosts or separate directories. Until
distributed account-level fencing exists, keep only one Paper process
connected to a given provider/account. SQLite WAL, checkpoints and lock files
must reside on durable local storage, not a network filesystem.

## CME 2026 review state

No reviewed snapshot is installed for 2026-10-07 through 2026-12-31. CME's
official schedule page exposes the holiday date ranges but directs users to
select the relevant date and product for trading hours and warns that schedules
can change. The currently readable static content does not provide the
product-filtered MNQ hour rows. Therefore the following exact MNQ date records
still need product-specific manual verification before a snapshot can cover
them: Columbus Day Oct 12; Veterans Day Nov 11; Thanksgiving trade dates Nov
25-28; Christmas trade dates Dec 24-26; and New Year's Eve Dec 31. Verify each
open, close, early close, reopen, and any intraday halt/maintenance exception.
No rule or date is inferred here. With no installed snapshot, the service's
calendar continues to fail closed.

After a human reviews the exact schedule, validate snapshot plus review
metadata with:

```powershell
python scripts/validate_cme_snapshot.py --snapshot <snapshot.json> `
  --review-record <review-record.json>
```

The review record binds the CME source URL, MNQ product, `America/New_York`,
coverage, UTC review time, and parsed snapshot identity. The command checks
schema and provenance metadata; it does not independently verify the truth of
the entered market hours. Fixture tests for Thanksgiving/Christmas exercise
schema behavior only, not CME 2026 session semantics.

## Free-host assessment

OCI publishes 3,000 OCPU-hours and 18,000 GB-hours per month for A1 compute,
which is quota-wise enough for a 2-OCPU/12-GB instance for a 31-day month.
Google's free Compute Engine allowance includes one e2-micro VM's monthly
hours in selected US regions, 30 GB-month standard persistent disk, and 1 GB
outbound transfer. These are published quotas, not availability or workload
guarantees. Based on the missing live provider/calendar and absent active RSS
measurement, neither host is approved for autonomous operation. OCI is the
more plausible future measurement target; the 1-GB e2-micro profile is not
established as suitable for this Python/HMM runtime.

## CME session calendar

`src/paper/cme_calendar.py` represents CME Globex trade dates, regular
maintenance/halt windows, the frozen strategy RTH (09:30--16:00 New York),
holiday closures, shortened sessions, and special-session overrides. All
boundaries use `America/New_York`, so daylight-saving transitions are handled
by the timezone database. CME trade dates assign Sunday evening to Monday and
weekday evening sessions to the next trade date.

Calendar holiday overrides must be supplied in a reviewed, versioned snapshot
with source URL and explicit coverage. An `early_close` entry must provide both
the RTH end and Globex close. A `special` entry must provide its full RTH and
Globex boundaries. Dates outside the declared coverage raise
`CalendarUnavailable`; the service reports a critical event and refuses to
evaluate strategies for that bar. It never guesses a holiday close. No official
holiday snapshot is bundled yet, so live use remains blocked until one is
reviewed and installed. CME publishes the [Globex holiday and trading-hour
schedule](https://www.cmegroup.com/trading-hours.html) and [Micro E-mini futures
contract hours](https://www.cmegroup.com/trading/equity-index/files/cme-micro-e-mini-futures-fact-card.pdf).
CME notes that holiday hours may change and are usually finalized about two
weeks before the holiday; refresh the snapshot from the current official
schedule before its coverage expires.

The regular equity-index Globex maintenance period is 17:00--18:00 ET. CME's
month-end settlement procedure also pauses equity-index futures 16:15--16:30 ET
on the month's final open trading date; the calendar applies that pause only
when the complete snapshot covers the rest of that month. See CME's [month-end
settlement procedure](https://www.cmegroup.com/trading/equity-index/fairvaluefaq.html).

The deterministic historical replay continues to mark the actual final
available RTH bar from that replay dataset. Realtime Paper can instead receive
the final-bar decision from `CMETradingCalendar`; this changes no ORB times or
strategy rules.

## Reconnect and catch-up contract

The `MarketDataSource` contract includes `backfill(after_timestamp,
before_timestamp)`. When an expected open-market minute is missing, the service
requests the exclusive interval, validates strict ordering and completeness,
and processes those bars before the newer queued bar. Missing expected bars,
duplicates, out-of-order results, unsupported backfill, or an uncovered
calendar interval stop the run in a critical error state; the newer bar is not
sent through strategy evaluation. Adapters that cannot backfill must fail closed
and leave the last processed checkpoint unchanged. A provider must keep its
stream alive across reconnects or surface a reconnecting source state while it
performs the same ordered catch-up.
